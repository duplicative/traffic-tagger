## Temporal-URL Correlation Strategy Implementation | 2025-01-05
Implemented sophisticated two-stage correlation strategy that matches sidecar events to HTTP records based on both temporal proximity and URL matching. Added normalized_url field to all HTTP records with compound indexes on (normalized_url, response_created_at) for efficient temporal queries. Completely rewrote correlation engine to: 1) Sort HTTP records and sidecar events by timestamp, 2) Map each event to the HTTP record that immediately precedes it temporally, 3) Calculate correlation time windows extending from each HTTP record to the next record for the same URL, 4) Apply correlation rules only on events within each record's time window. This prevents cross-contamination when the same URL is visited multiple times, ensuring events correlate only with their originating HTTP request. Updated RuleEngine.run_correlation_analysis() to accept time window parameters and filter enrichment events by temporal boundaries. Added correlation metadata tracking (correlated_events, correlation_window) to HTTP records. Created migration script (add_normalized_url_field.py) to backfill normalized_url on 909 existing records and establish indexes. Developed comprehensive test suite (test_temporal_correlation.py) demonstrating correct correlation of multiple visits to the same URL at different times with zero cross-contamination between visits. Added python-dateutil dependency for ISO timestamp parsing.

## Correlation Timeline API Endpoints | 2025-01-05
Implemented backend REST API endpoints for correlation timeline visualization: GET /api/correlation-timeline returns paginated HTTP records sorted by timestamp with nested correlated sidecar events, including time deltas (seconds after HTTP response), event type statistics, and correlation window metadata. GET /api/correlation-stats provides comprehensive metrics including total HTTP records, correlation rate percentage, enrichment event counts by type (dom_snapshots, js_executions, storage_states), average events per record, and max events per record. Both endpoints support filtering and provide detailed pagination and summary information to power frontend timeline UI. Ready for frontend implementation.

## Automatic Correlation Engine | 2025-01-10
Implemented automatic correlation execution in watcher service eliminating need for manual correlation runs. Added _run_correlation() method that executes temporal-URL correlation on all HTTP records by iterating through unique normalized_url values and calling run_correlation_for_url() for each. Integrated automatic correlation triggers: (1) Post-CSV ingestion - automatically correlates new HTTP records immediately after CSV file is processed and added to database, (2) Periodic schedule - runs correlation every 5 minutes (configurable via correlation_interval parameter) to process any new enrichment events captured by sidecar extension. Added check_periodic_correlation() method to monitor elapsed time and trigger correlation when interval threshold reached. Correlation intelligently skips execution when no enrichment events exist in database. Created run_correlation.py standalone script for manual on-demand correlation execution with detailed progress reporting and statistics (URLs processed, records correlated, correlation rate). Created AUTO_CORRELATION.md documentation covering automatic behavior, configuration options, monitoring via logs, troubleshooting, and best practices for different use cases.
